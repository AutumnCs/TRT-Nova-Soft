TRT Nova 植宠系统技术概览

微信小程序 + SCF + MySQL + OneNET

一个植宠养护小程序，前端使用微信小程序原生页面，后端由多个 SCF 云函数承载，MySQL 作为主业务数据存储，OneNET/EMQX 负责设备接入与命令下发。

01

系统概览

TRT Nova 系统是一个植宠养护小程序，包含以下核心组成部分：

前端微信小程序原生页面
SCF 后端auth-scf、api-scf、ingest-scf、agent-scf、admin-scf、history-cleanup-scf
主数据库MySQL，承载核心业务数据
设备基础设施OneNET/EMQX，负责设备接入与命令下发
未来基础设施Redis 缓存层（已规划，T1 阶段启用）

当前生产流程

设备遥测→ingest-scf→MySQL
小程序认证→auth-scf→JWT
小程序 API→api-scf→MySQL / OneNET
管理后台→admin-scf→MySQL / 运营数据
02

架构总览

设备遥测上行
实体设备→ OneNET→ ingest-scf→ MySQL
小程序业务交互
微信小程序→ auth-scf→ MySQL
微信小程序→ api-scf→ MySQL, OneNET
微信小程序→ agent-scf→ MySQL
管理后台
Admin Web→ admin-scf→ MySQL

控制流与回声

控制 小程序→ api-scf /device/cmd→ OneNET→ 设备
回声 设备重新上报→ ingest-scf→ device_latest→ 小程序

04

SCF 后端服务

auth-scf

微信登录、用户落库、JWT 签发。

入口: dist/scf/auth-scf/index.js

api-scf

设备、待办、日记、植物库、用户资料与下行控制。

入口: dist/scf/api-scf/index.js

ingest-scf

OneNET/EMQX 数据接入、归一化和历史写入。

入口: dist/scf/ingest-scf/index.js

agent-scf

只读植物助手、规则、轻量知识检索和可选 LLM。

入口: dist/scf/agent-scf/index.js

admin-scf

管理后台 API、用户管理、知识管理、设备服务、日志。

入口: dist/scf/admin-scf/index.js

history-cleanup-scf

历史数据定期清理。

入口: dist/scf/history-cleanup-scf/index.js

05

数据模型

主要实体及其职责：

users用户身份与资料
devices设备主数据和 IoT 身份
device_acl用户与设备关系，别名、位置、植物类型
device_latest设备最新状态（首页读模型）
device_history_raw原始历史数据
device_history_agg聚合趋势数据
todos养护待办
plant_library植物知识主数据
user_plant_favorites用户植物收藏
植物日记相关月/日查询与记录数据
关键模型缺口：缺少独立 PlantPet 实体。植物个体通过 device_acl 表达，造成更换设备时历史难以延续。

07

关键架构决策

01客户端不直接访问 OneNET 和数据库
02OneNET/IoT 平台负责设备接入，业务后端负责用户和领域逻辑
03productId + deviceName 形成设备逻辑标识
04devices 与 device_acl 分离
05device_latest 作为首页和详情的当前状态读模型
06控制意图与设备真实状态分离
07Agent 当前保持只读，动作能力后续通过独立确认接口开放
08植物知识优先结构化，规则、知识和 LLM 分工
09先使用 SCF + MySQL 验证闭环，再根据证据引入更重基础设施
