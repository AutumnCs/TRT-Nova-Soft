# 旧实例直连兼容验证

日期：2026-09-09。范围：独立 Cloud 候选的数据库连接配置，不部署云函数，不执行迁移，不修改旧实例。

## 调整

旧 LastScf 连接池只传入主机、端口、库名和账号凭据，没有 SSL 配置。此前候选把旧链路归为 private-network，与实际公网非 TLS 端点不符，属于接入配置偏差。

按用户确认新增并选用 legacy-direct，复用旧链路。private-network 和 required 保留但暂不选用；required 的证书、主机名和可选 CA 校验保持不变，不做失败后自动明文重试。业务连接池代码无需重写。

- 配置、渲染器与五个函数的运行校验接受三种明确模式。
- 迁移和内容导入工具在云模式缺失或未知时，于连接前报错；本地测试入口不变。
- 实际端点只保存在被 Git 忽略的 candidate.config.local.json；新业务仍使用独立库，没有复制密码或旧数据。
- 本地配置只完成数据库字段，其余部署占位符和未验证标记保留，不构成可发布配置。

## 边界与恢复

当前链路没有 TLS 加密；这是用户明确选择的临时兼容方式，不是私网或 TLS 验收通过。尚未执行建库、建账号、授权、迁移、SCF 上传或云端出站验证。

恢复时将 database.tlsMode 改为 private-network（先确认私网可达），或 required（先确认目标支持 TLS，再按需提供 DB_SSL_CA），重新渲染并配置 SCF。切换运行模式需要新的函数进程/实例生效，已缓存的连接池不会自动热切换。

本次没有新增本地替身或修改产品/Agent 权限。LC-04 的云端验收保持待验证。
