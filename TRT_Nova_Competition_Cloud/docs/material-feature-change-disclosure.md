## 云端适配

业务后端通过三个独立 SCF Function URL 提供 Auth、API 和 Agent 接口，使用 index.main_handler 入口与 SCF 环境变量。MySQL 保存业务数据，CloudBase 保存图片和文档原文件。

附件流程包含上传准备、原生上传、服务端内容校验、持久化登记及引用清理。替换、撤回、删除和失败重试维持文件与业务记录一致。未完成上传有 24 小时清理宽限，已引用附件不因此自动删除。

2026-09-10 已按用户要求发布原审核知识，并部署、启用原有 history-cleanup-scf 的每分钟维护定时器。新增的是固定后台清理的真实云端运行，不是新的产品入口或 Agent 后台执行权限；无新增 HTTP 入口、运行角色或模型工具权限。自然清理 9 个旧测试文件、保留原头像的专项通过；失败重试故障注入未在本次执行。以下数据库准备段落保留为此前阶段记录。

本次适配不删除产品入口，不自动迁移旧数据。测试部署使用独立函数、业务库和附件范围；不覆盖现有服务。

数据库连接调整：按用户要求新增并选用 legacy-direct，复用已核实的旧实例公网非 TLS 链路。原 private-network 和 required 模式保留但暂不选用，required 的证书与主机名校验不变。没有自动 TLS 降级，不修改数据库服务参数，不改业务表、账号授权或旧实例代码。此调整是连接配置兼容修正，不是新库或 SCF 连通验收。

后续数据库准备：用户明确取消新账号方案，使用现有账号创建并初始化独立新库。实际新增 30 张表、1 个触发器及基线脚本自带的 4 条草稿植物资料，未发布知识内容、导入旧用户数据或更改账号授权。事务写入、触发器及回滚验证通过；没有持久化测试用户、附件或聊天记录。该阶段不包含 SCF 部署。

## Agent 与权限

当前使用内部 PlantPetRuntime，在已鉴权的单次请求内执行受限模型与工具调用。MySQL 是会话和业务记录的持久化来源。

模型不能直接创建正式任务、绕过账号归属或控制设备。自动跨会话摘要只在用户启用后处理有当前用户原话依据的低风险事实。没有后台持续执行、多 Agent 或自主设备控制。

评测工具只用于验证，不构成生产 Agent 权限。
