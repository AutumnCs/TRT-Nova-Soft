# M7 页面跳转性能优化与人工验收指南

## 1. 本轮结论与边界

本轮只修改导航反馈、页面生命周期、展示缓存和登录后的跳转，不修改 Agent runtime、意图识别、RAG、记忆策略、Tool Calling 权限或业务副作用。

实测将耗时分成了四段：

1. 点击后 Tab 是否立即给出反馈；
2. 微信路由是否到达目标页面；
3. 页面结构化业务数据何时可用；
4. 图片何时解析并可展示。

本地后端相关接口通常为数毫秒，页面首次进入的主要长尾来自微信开发者工具首次创建页面执行环境。它和同一页面第二次进入必须分开记录，不能再把 `await miniProgram.switchTab()` 的自动化 RPC 总时长直接叫作“产品路由耗时”。

## 2. 已落地的优化

### 2.1 导航即时反馈与防重入

- 点击底部 Tab 后，选中态先更新，再发起 `wx.switchTab`；
- 点击当前 Tab 不再重复调用路由；
- 跳转尚未结束时忽略重复点击；
- 跳转失败时恢复原选中态；
- 登录成功后移除了原先固定的 800 ms 等待，资料状态写入视图后立即进入首页。

### 2.2 页面采用“旧内容先显示，后台刷新”

- 首页再次显示时不清空植宠、任务和天气；
- 日历再次显示时保留现有日期网格和任务；
- “我的”再次显示时保留昵称、头像和成长记录；
- AI 助手返回同一植宠、同一会话时保留历史消息和未发送草稿，再静默同步服务端会话；
- AI 助手的后台旧快照只有在账号、会话和本地消息版本都未变化时才允许落到界面，发送中的新消息不会被延迟回包覆盖；
- 当前会话偏好按“账号 + 植宠/全局会话”隔离，两个账号不会互相覆盖上次选中的会话；
- 首页养护摘要、个人资料或助手会话后台刷新失败时继续显示最后一次成功内容，并明确提示刷新失败；
- 只有该账号从未成功加载过页面数据时才显示整页 loading；
- 所有展示快照都按当前登录 openid 校验，账号切换时不能复用前一账号内容。

### 2.3 知识库与图片缓存

- 知识库普通进入复用 `KnowledgeService` 已有缓存；
- 本地图片的 `fileId -> 本机展示路径` 建立持久索引；
- 索引按当前账号隔离，切换账号不会命中前一账号索引；
- 小程序重启后先验证本机文件是否仍存在，存在则不再请求 `/media/resolve`；
- 缓存文件丢失时自动重新解析并修复索引；
- 多张图片并行写入，单张写入失败不会阻止文字与其他图片展示；
- “清理图片缓存”会同时清理内存缓存、持久索引和本机缓存文件，不删除服务端原图；
- 清理期间新的图片解析会等待，旧解析也不能回填已删除路径或误删清理后重新写入的同名文件；
- 缓存代际变化时只允许原始 HTTPS 地址作为安全回退，不返回可能已经失效的本机路径。

### 2.4 已否决的配置试验

- 开启 SWC 后，本机微信开发者工具首次路由明显变慢，已恢复原配置；
- `lazyCodeLoading` 开/关在重复受控测量中没有稳定收益，因此保留原来的 `requiredComponents`，避免为了偶然单次结果牺牲小程序启动表现。

## 4. 主路径人工验收

### 4.1 登录进入首页

1. 从“我的”退出登录；
2. 完成开发版登录；
3. 点击最终确认/登录按钮；
4. 观察是否立即开始进入首页。

通过标准：

- 不再固定停留约 800 ms；
- 连续快速点击确认不会重复跳转；
- 跳转失败时按钮不会永久锁死。

### 4.2 四个主 Tab 的首次与热切换

按以下顺序完整执行两轮：

```text
首页 -> AI助手 -> 日历 -> 我的 -> 首页
首页 -> 我的 -> 日历 -> AI助手 -> 首页
```

第一轮记录“本次编译后首次创建页面”，第二轮记录“已创建页面的热切换”。然后再连续往返 10 轮。

每一次点击都检查：

- 手指抬起后，目标 Tab 图标和指示条立即变为选中状态；
- 快速连点同一个 Tab 不会重复跳转或闪屏；
- 快速点击两个不同 Tab 时不会出现页面与底部选中态错位；
- 返回已看过的首页时，植宠卡片、今日任务和天气不先消失；
- 返回日历时，月历网格不先变成整页“正在同步”；
- 返回“我的”时，昵称、头像、成长记录不退回占位状态；
- 返回 AI 助手同一会话时，历史消息和输入框草稿仍在，后台同步不能把它们清空。

建议通过线：

- 点击反馈：肉眼即时，目标为 100 ms 内；
- 同一开发者工具进程中第二次及以后进入主 Tab：目标页面壳应在 300 ms 内出现并可交互；后台数据刷新允许稍后稳定，但不应阻断旧内容；
- 后台刷新过程中旧内容持续可读、可滚动；
- 不能出现重复跳转、选中态错位、整页闪空或跨账号旧数据。

### 4.3 普通页面与知识库

依次检查：

1. 我的 -> 知识库 -> 返回；
2. 再次打开知识库；
3. 首页 -> 植宠详情 -> 返回；
4. 日历 -> 新建任务 -> 返回；
5. 我的 -> 系统设置 -> 关于我们 -> 返回。

通过标准：

- 返回按钮均可用，页面栈不紊乱；
- 第二次进入知识库不应重新长时间等待文章列表；
- 从“关于我们”返回不产生多余震动；
- 表单返回后原页面内容仍在，不重新闪空。

## 5. 图片缓存专项验收

准备一个包含头像、植宠封面、成长照片或图片会话附件的账号。

第一轮：

1. 打开首页、“我的”和 AI 助手，使图片全部显示；
2. 在 Network 面板记录 `/media/resolve` 请求；
3. 正常关闭并重新打开当前开发者工具项目，不清除小程序存储；
4. 再次进入相同页面。

通过标准：

- 第二轮同一账号、同一 `fileId` 不再重复请求 `/media/resolve`；
- 图片能从已验证存在的本机缓存恢复；
- 清理图片缓存后，下一次进入允许重新请求并重建缓存；
- 换另一个账号后不能复用前一账号的持久索引；
- 任一图片失败不影响昵称、植宠文字、任务或对话文本显示。

## 6. 冷启动与微信开发者工具首次页面创建

冷测必须单独记录，不能和热切换平均到一起：

1. 关闭当前项目窗口；
2. 重新通过微信开发者工具打开同一路径；
3. 首页稳定后，依次首次打开 AI 助手、日历和“我的”；
4. 记录第一次；
5. 再重复同一路径，记录第二次。

当前自动化证据表明，开发者工具首次创建某个页面执行环境可能出现约 1.9–4.0 秒且波动明显的额外开销，而同页第二次通常降到 0.09–0.18 秒。最后一次探针中，日历、我的和知识库页面自身记录的原生 `firstRender` 分别约为 324 ms、669 ms 和 394 ms，说明外部等待中包含开发者工具页面注入与自动化协议开销。这一段必须在真机预览中复核；如果只有开发者工具冷样本慢、真机和热切换正常，应归类为开发工具首次注入/页面创建开销，不能误判为后端接口慢，也不能继续通过增加业务缓存来掩盖。

### 6.1 为什么本轮没有继续做分包或强制预热

- 微信的 [`preloadRule`](https://developers.weixin.qq.com/miniprogram/dev/framework/subpackages/preload.html) 只预下载分包，不会预创建具体页面或提前运行页面生命周期；
- [官方分包规则](https://developers.weixin.qq.com/miniprogram/dev/framework/subpackages/basic.html) 要求 `tabBar` 页面留在主包，所以四个主 Tab 不能靠迁入分包解决首次切换；
- 项目已经启用官方的[按需注入](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/lazyload.html) `lazyCodeLoading: "requiredComponents"`；
- 官方确有 Android 端的 [`wx.preloadWebview`](https://developers.weixin.qq.com/miniprogram/dev/api/base/performance/wx.preloadWebview.html)，但它只准备“下一个页面”的通用 WebView，不能指定页面，而且框架默认已采用静态预热；
- 因此本轮没有为了开发者工具冷态数字把四个 Tab 合成单页、迁移渲染引擎或增加不可见页面实例。这些做法会改变生命周期和返回栈，风险显著高于当前证据支持的收益。

如果 Android 真机仍稳定复现首次切换超过 1 秒，可另开 A/B：只把 `window.handleWebviewPreload` 从默认策略改为 `auto`，同时保留一组原配置对照；iOS 不应以该 API 作为解决方案。最终表现应按[微信客户端真实运行环境](https://developers.weixin.qq.com/miniprogram/dev/framework/runtime/env.html)判断，而不是只看开发者工具。

## 7. 弱网与失败回退

先让四个主 Tab 各成功加载一次，再在开发者工具 Network 面板切换到离线或极慢网络，重复四 Tab 切换。

通过标准：

- 已加载页面继续显示上次内容；
- 不因后台刷新失败而清空整页；
- 恢复网络后重新进入或下拉刷新能恢复最新数据；
- 底部 Tab 路由失败时选中态回滚；
- 账号归属校验仍有效，不为了缓存放宽 owner/openid 边界。

## 8. 自动测试

```powershell

```

本轮新增自动覆盖：

- 当前 Tab 忽略；
- 路由防重入；
- 连续第三次点击仍不能穿透进行中的路由锁；
- 乐观选中与失败回滚；
- 登录后立即进入首页且防重复提交；
- 四个主 Tab 的旧内容优先展示与后台刷新失败回退；
- 助手后台旧会话快照不能覆盖发送中的新消息；
- 全局会话、草稿和上次选中会话均按账号隔离；
- 图片缓存跨服务实例/小程序重启复用；
- 图片持久缓存按账号隔离；
- 两组媒体并发解析不会互相覆盖缓存索引；
- 本地存储索引写入失败时，已解析图片仍正常显示；
- 清理缓存与解析交错时不返回失效本机路径；
- 旧解析、清理和同 fileId 新解析三方交错时，旧任务不能误删新缓存。
