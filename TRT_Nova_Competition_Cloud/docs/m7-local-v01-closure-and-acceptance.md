## 1. 第一性原理收口结论

PRD v0.1 的本地核心闭环不是“页面都能打开”，而是同一 JWT 用户、同一 PlantPet 和同一组真实业务对象贯穿以下因果链：

`真实登录 -> 建立月季档案及持久封面 -> 图片进入会话草稿 -> 真实 Vision -> 用户主动另存观察 -> 明确任务意图只产生候选 -> 用户确认后写任务 -> 首页/日历读取同一任务 -> 打卡 -> 图文成长记录 -> 重开仍恢复 -> AI 记忆与 RAG 可见来源`

本轮没有增加通用 Agent framework、模型自主 tool calling、第二分类模型、后台任务、多 Agent、handoff、subagent、checkpoint 或新的业务写权限。所有业务副作用仍由既有确定性门禁和用户确认控制。

### 1.1 2026-09-01 验收反馈的边界

- 用户实测发现一般 Query 仍可能被确定性规则层错误拒绝；既有黄金语料通过不能反证真实交互不存在漏放/误拦。
- 用户实测发现“以后叫我 dola”在后续“我是谁”中没有形成符合预期的会话连续性；`AI 记忆与 RAG 来源`的 E2E 只证明来源卡与已有结构化业务记忆可读，不能证明自由聊天称呼会被长期记住。
- 用户明确要求本轮不要继续改 Agent。因而本轮没有改意图路由、规则、Prompt、模型调用、记忆/RAG、工具权限或副作用门禁；以上两项作为下一版 Agent 设计的真实复现样例保留，不以 UI 修复冒充完成。

## 2. 本轮补齐的用户能力

1. 首页“添加植宠”先让用户选择“拍照识别后建档”或“手动填写档案”。拍照路径复用已经实现并验证的 AI 附件草稿和 Vision 链，不建立第二套图片分析流程；手动路径继续进入既有建档页。
2. 建档页把“用户已主动选择封面”作为显式页面状态；后续选择月季品种时不再覆盖自定义封面。
3. 图片分析严格区分“观察”与“创建任务”。“只观察图片，不要创建任务”不产生任务候选；只有明确安排、创建、提醒或制定任务的表达才可能生成候选。
4. AI 任务候选仍必须进入既有任务表单供用户修改；没有 `confirmed=true` 时，后端继续拒绝写入。
5. “我的 -> 系统设置”从“开发中 + 震动”变为真实设置页，集中提供个人资料、城市、站内提醒状态、微信订阅消息依赖状态、AI 记忆与隐私、图片与数据使用、显示缓存、版本、关于和退出登录。可用入口不再震动。
6. 增加独立 M7 API/数据库冒烟和微信开发者工具全流程 E2E。两者都从 `/auth/login` 开始，不以 `/dev/token` 作为登录验收依据。

## 5. 本轮发现并修复的问题归类

1. **否定任务意图被误判**：`hasExplicitTaskIntent` 过去看见“创建任务”字面词就返回真，忽略“不要”。这是 M6 新意图门禁的集成回归，不是旧项目行为；现已增加否定优先，同时保留“不要忘了明天提醒我浇水”这类真实正向表达。
2. **品种选择覆盖自定义封面**：建档页没有独立记录用户是否已改封面，选择品种后会回填品种图。这是 M1 表单状态联动缺口；现以 `coverChanged` 保留用户选择。
3. **系统设置仍是开发中**：这是旧项目残留的未开放入口；M7 只补齐支撑 P0 闭环所需的最小设置汇总页，没有引入新的后台配置中心。
4. **新设置页首版双导航与胶囊遮挡**：这是 M7 新页面实现问题；现关闭该页原生导航，复用项目现有自定义导航安全区做法，并在微信开发者工具重新取证。
5. **DevTools WebView 就绪竞态**：这是验收脚本问题，不是产品功能问题；脚本现先得到可用页面再清理登录态，并保留重试，避免连接成功但页面元数据尚未生成时误报产品失败。
6. **个人资料头像框与字段对齐**：头像按钮与外圈同尺寸、页面末尾主题规则再次把输入覆盖成右对齐，均为旧页面遗留样式；现把头像内容收进边框、状态点移到框外，并对可编辑字段恢复左对齐。
7. **知识库返回与滚动截断**：旧页面没有显式返回按钮，同时页面和内部 `scroll-view` 都可滚动，安全区标题随外层滚动进入胶囊/刘海区域；现改为固定安全顶栏加唯一内容滚动区，返回失败时才回首页兜底。
8. **“关于我们”返回振动**：旧页面把普通返回也当成反馈动作；现只移除返回振动，隐私协议、用户协议和分享等明确操作的既有振动不变。
9. **规则层与会话称呼连续性**：用户验收确认仍不符合预期。本轮遵守“不要改 Agent”的边界，没有用新正则、临时记忆或 Prompt 补丁掩盖问题。

## 6. 性能口径

最终结果以 `m7-devtools-result.json` 为准。当前自动化区分两种时间：

- **业务刷新**：页面已经编译后，首页植宠/任务刷新和日历任务刷新都要求 `< 2 s`；这是 M7 的开发者工具业务门禁。
- **AI 首反馈**：Chat 和 Vision 提交后先插入可见的渐进反馈，要求 `< 1.5 s`；总模型时间另行记录但不伪装成流式 token。
- **开发者工具导航耗时**：`reLaunch/switchTab` 含编译和自动化协议开销，只作观测，不称为实体手机首屏性能。
- **实体手机冷启动**：仍属于 M8。需要指定手机、微信版本、同一网络条件下连续 5 次记录，M7 不越权代替。

2026-09-01 最终一次完整 E2E 的实测值如下；模型总耗时受网络与上游服务影响，只作为本次证据，不承诺为产品 SLA：

## 7. 三分钟比赛演示脚本

演示前只准备：本地/未来云端服务健康、一个可登录测试账号、已知月季图片、网络稳定。不能提前把假任务或假日记塞进演示账号冒充现场结果。

| 时间 | 操作 | 评委应看到的唯一重点 |
|---|---|---|
| 0:00–0:20 | 微信一键登录并进入空花园 | 账号隔离，空状态不借旧数据 |
| 0:20–0:45 | 添加植宠 -> 手动建档，选择月季图作封面并保存 | 档案、品种和真实封面成为同一 PlantPet |
| 0:45–1:15 | 回到添加入口选择拍照识别；图片先进入草稿，补充“观察当前状态，不要创建任务”后发送 | 图片不会选中即发送；真实 Vision；普通观察不误建任务 |
| 1:15–1:40 | 点击另存观察；再问“请安排今天观察月季叶片的任务” | 观察与任务是两类对象；只有明确意图才给候选 |
| 1:40–2:00 | 打开候选表单，确认；回首页查看今日任务 | AI 不能直接写，用户确认后首页读取真实任务 |
| 2:00–2:20 | 进日历完成任务 | 同一任务完成并更新连续计划事实 |
| 2:20–2:40 | 新增一条带月季照片和文字的成长记录，退出后重开 | 图和文字持久化，不是页面临时状态 |
| 2:40–2:55 | 回 AI 问月季浇水判断，展示来源；打开记忆 | 回答有 published 来源，记忆有业务来源和时间 |
| 2:55–3:00 | 一句话收束 | “NOVA 把档案、观察、任务、日记和有来源知识连成一个可追溯闭环。” |

若模型请求在演示现场失败，应直接展示明确失败状态并切换到手动记录；不得展示预制 AI 成功卡冒充现场调用。

## 9. 重大功能变更披露

- **保留**：四 Tab、既有建档/任务/日历/日记/AI/记忆能力、M6 两级附件菜单、图片草稿、真实 Vision、用户确认门禁、published-only RAG、结构化记忆、全部旧设备兼容页。

## 10. 本地化妥协与进入下一阶段条件

M7 **没有新增、改变或关闭新的本地化妥协类型**。验收工具只复用：

- LC-02 本地 `/auth/login` 同契约适配；
- LC-04 本地 MySQL 业务数据；
- LC-05 本地媒体 provider；
- LC-07 仓库外临时 Chat/Vision Key；
- LC-08 开发者工具 localhost 例外；
