# 用有效分支投影承载会话，用确认候选承载可写副作用

M7 Phase 4/5 采用兼容式事件会话，而不是把聊天记录、长期记忆和业务状态合并成一份模型上下文。既有消息表继续保存可加载的消息快照；新增会话事件记录轮次提交、重新编辑分支和撤回等审计事实；Context Projector 只把当前有效且完整的用户/助手轮次投影给模型。重新编辑在事务中复制目标消息之前的有效前缀并创建新会话，撤回在事务中抑制最近完整轮次及其未确认候选。

长期记忆只召回当前认证账号下、已由用户确认且与本轮相关的偏好；植宠档案、任务、养护记录和设备状态继续由各自业务表拥有，不复制为自由文本记忆。模型或确定性能力策略只能产生 `memory_preference` 与 `care_task` 的 `pending` 候选，不能直接写入长期记忆或正式任务。用户在独立 API 中预览、编辑或确认后，服务端重新校验 JWT owner、植宠归属、字段 schema、状态和幂等键，再在事务中完成写入。

每次发送携带 `clientTurnKey`。服务端在调用模型和扣减配额之前检查已提交事件，并在并发重复到达时依靠唯一键返回原轮次，因此网络重试不会重复消息或候选。任务确认另外用候选键记录正式任务创建结果，重复确认返回同一任务。

## Considered Options

- 只修改或删除原消息行：拒绝，因为会失去分支与撤回审计依据，并容易在失败时留下半轮历史。
- 完整 event sourcing 重写全部消息和业务表：暂不采用，迁移风险和参赛版收益不匹配；当前使用“消息快照 + 追加审计事件”的兼容方案。
- 模型直接调用写任务/写记忆工具：拒绝，模型选择工具不构成用户授权，且无法可靠处理预览、编辑、重试和越权参数。
- 自动摘要全部聊天作为长期记忆：拒绝，容易把误解、敏感信息和植宠业务事实复制成第二份真相。

## Consequences

- `ai_conversation_events`、`ai_action_proposals`、`care_task_creation_keys` 和 `ai_message_media_links` 必须先于包含本 ADR 代码的 Agent/API 版本部署。
- 会话加载必须以服务端候选状态覆盖旧消息响应中的候选快照，过期、确认或取消后切换页面不能“复活”旧按钮。
- 记忆和任务候选均默认等待确认；普通养护建议、图片中的建议动作、否定、讨论和模糊表达不得自动形成正式任务。
- 正式写入继续属于业务 API，而不是 `PlantPetRuntime`；关闭 M7 灰度开关可以回落 legacy 回复，但不能回滚已经确认的业务记录。
- 当前实现不是完整 event sourcing，也没有后台自治、跨 Agent、任意工具、设备写入或无需用户确认的长期记忆。
