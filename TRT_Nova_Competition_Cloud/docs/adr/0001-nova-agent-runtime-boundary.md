# NOVA 采用 LLM-first 对话并把正式写入留在 Agent loop 之外

NOVA 拟删除以语义正则决定“是否回答”的门控，让模型负责理解、陪伴表达和自然边界；确定性策略只负责身份、资源归属、知识发布状态、工具参数和风险边界。Agent loop 可以读取授权事实并生成任务候选，但不持有正式任务、养护记录、植宠档案或设备动作的直接写入能力；正式写入继续由用户确认后的业务系统拥有。这样既减少开放语言中的误拒绝，又保证提示词或工具选择不能越过业务授权。

## Considered Options

- 继续扩大正则分类器：拒绝，因为一次误分类会同时切断模型、历史、记忆、RAG 和任务能力。
- 全部交给提示词：拒绝，因为真实模型探针已经出现养护知识漏检索，且模型参数不能替代权限校验。
- LLM-first 加窄策略和候选写入：拟采用，在自然交互和可验证副作用之间保留清晰边界。

## Consequences

- 会话、长期记忆、业务事实和已发布知识必须分别投影到模型上下文。
- 工具执行器必须再次校验当前用户、资源归属和参数；模型选择工具不构成授权。
- PI 官方包、自建兼容 loop 或自定义运行时的技术路线仍需另行决定，本 ADR 不预设实现依赖。
