# M7 Phase 3 受控灰度结果

> 历史/目标文档提示（2026-09-08）：本文保留该阶段的配置、调研或实施记录，不作为当前能力与验收状态清单。旧记忆、额度、rollout 和云端结论如与后续版本不同，以当前入口为准。 当前产品见[先看这里](./先看这里.md)，技术事实见[当前架构](./current-architecture.md)。

> 状态：2026-09-03 本地实现、真实 provider 探针和真实本地 HTTP 链路已通过；灰度总开关仍默认关闭，未部署到体验版、正式版或腾讯云。

## 1. 本阶段结论

Phase 3 没有把 legacy Agent 一次性替换掉，也没有继续用回答正则判断普通 Query “值不值得回答”。它在现有 `/agent/chat` 外层增加了一个按账号和会话稳定抽样的 `PlantPetRuntime` 接管器：只有本轮所需能力已经迁移，且模型输出通过工具、来源、隐私和完整性门禁时，新 runtime 才保存并返回回复；其他情况继续由 legacy 链路完成。

```text
已鉴权 /agent/chat
        |
        v
账号 + 会话 HMAC 稳定抽样
        |
        +-- 未抽中 ------------------------------> legacy
        |
        v
能力完整性门禁
        |
        +-- 任务/记忆/附件/当前植宠/高风险等 ----> legacy
        |
        v
PlantPetRuntime + 三个只读工具
        |
        +-- 超时/工具失败/来源缺失/隐私不完整 ---> legacy
        |
        v
保存一次新 exchange，并返回 controlled_rollout 回复
```

这使 `1+1等于几`、`1+2是多少个月季`、`1+2是多少朵玫瑰花`、翻译、常见互动和通用植物知识可以进入 LLM，而不是因为标点或植物词被旧回答正则截断。同时，任务、长期记忆、当前植宠私有状态等尚未迁移能力仍由原链路负责，不用“模型似乎能回答”冒充权限已经迁移。

## 2. 灰度与回滚

- `AGENT_ROLLOUT_ENABLED=false` 是默认值和总回滚开关；关闭后请求行为回到 legacy，且不会增加新 runtime 模型调用。
- 开启后，`AGENT_ROLLOUT_SAMPLE_RATE` 默认建议从 `0.1` 开始，取值限制在 `0..1`。
- 抽样键是后端鉴权 `openid + sessionKey` 的 HMAC 指纹，不使用 Query 文本；同一账号同一会话不会随每句话随机切换实验组。
- `AGENT_ROLLOUT_COHORT_KEY` 应使用独立密钥；留空时依次回退 Shadow 指纹密钥和 `JWT_SECRET`。
- 步数、工具数、超时和输出上限分别由 `AGENT_ROLLOUT_MAX_STEPS`、`AGENT_ROLLOUT_MAX_TOOL_CALLS`、`AGENT_ROLLOUT_TIMEOUT_MS`、`AGENT_ROLLOUT_MAX_TOKENS` 控制。
- 当前没有通过代码或部署配置实际开启体验版/正式版灰度；需要目标环境独立授权、配置和回滚演练。

## 3. 能力所有权

### 3.1 可由 Phase 3 接管

- 问候、致谢、关系互动等普通对话；
- `我是谁` 等明确账号称呼读取，仅允许后端按当前 JWT 账号读取昵称，并要求回复说明昵称不等于真实身份及隐私边界；
- 算术、翻译、常见事实、短笑话等轻量互动；
- 月季、龟背竹等通用植物知识；植物知识由策略要求先读取 `published` 内容，但策略只决定事实补充，不决定 Query 是否允许回答；
- 编程、猜想、投资等职责边界问题的自然收束，模型没有对应执行工具。

### 3.2 继续由 legacy 负责

- 任务、提醒、日程、计划、安排与打卡；
- 长期记忆的写入、召回、删除和称呼偏好；
- 图片、文档、文章上下文和显式“选择功能”；
- 当前/选中植宠状态、设备事实及隐式代词指向；
- 农药、误食等高风险内容；
- 跨账号、伪造资源 ID、安全边界与硬件请求。

这些保留项不是新 runtime 的拒绝列表，而是尚未迁移能力的所有权表。Phase 3 不改变它们原有的 RAG、记忆、附件和确认式任务流程。

## 4. 结果完整性门禁

新 runtime 结果出现以下任一情况时不会展示给用户，而是回落 legacy：

- provider 失败、运行超时、未完成或空回复；
- 工具失败、非法工具参数，或模型尝试非必要读取私有账号/植宠信息；
- 植物知识应检索而未检索、命中知识却缺少可读来源、无命中却给出确定结论；
- 身份回复未说明账号称呼和隐私边界；
- 泄露内部 runtime/tool 名称，或声称已经创建任务、提醒、档案、日记等实际写入；
- 返回内容超过受控长度。

接管成功时只保存一次用户/助手 exchange，记录 Chat 次数和 provider token；`memoryUpdated=false`、`taskSuggestions=[]`。接管失败时不保存草稿，若 provider 已返回 token 用量则仍记录成本，然后由 legacy 保存并回复。日志只含 HMAC 指纹、结果类别、步骤/工具/耗时等指标，不记录 Query、openid、昵称、植宠正文、知识正文或模型草稿。

## 5. 验证证据

### 5.1 自动化回归

- Phase 3/Shadow 专项 22/22：能力所有权、稳定抽样、普通算术放行、身份隐私、RAG 来源、保存一次、provider 超时/工具故障回落和脱敏日志均有直接测试；
- 全仓库 `npm test`：342/342；
- 新增/接入 JavaScript 通过 `node --check`；
- `node scripts/check-ai-context.mjs`、五个 SCF 部署目录检查和 `git diff --check` 通过。

### 5.2 42 场景真实 provider 探针

证据：`evals/m7-agent/rollout-provider-probe.latest.json`。探针使用内存账号/植宠夹具和只读发布知识 fallback，不连接业务 MySQL、不保存模型原文、不执行业务写入。

| 指标 | 结果 |
|---|---:|
| 产品合同总场景 | 42 |
| 能力门禁选中 | 19 |
| 新 runtime 接管 | 18 |
| 安全回落 | 1 |
| legacy 误拒候选 | 16 |
| 其中被新 runtime 接管 | 15 |
| 答案级语义断言 | 10 / 10 |
| 缺失预期工具 | 0 |
| 非必要私有工具 | 0 |
| 阻断或失败工具调用 | 0 |
| 业务写入 | 0 |
| 本地直连 provider P50 | 1948 ms |
| 本地直连 provider P95 | 6519 ms |
| 最终证据轮总 token | 25838 |

唯一回落是 `knowledge-no-match`：已发布知识无匹配结果，但模型没有在最终回复中明确表达不确定性，结果门禁以 `knowledge_uncertainty_missing` 拒绝其接管。该场景由 legacy 接手，证明“安全回落”实际生效；它不应通过放松证据规则换取 100% 接管率。

为修正真实探针暴露的提示词、空策略块和投资边界问题，本阶段共执行四轮 42 场景 provider 探针，报告 token 累计 101596；表中 25838 仅是修复后的最终证据轮。真实 HTTP smoke 的调用不计入这个探针累计值。

### 5.3 真实本地 HTTP 链路

使用现有 `zhichong_v01_local` 数据目录临时启动 MySQL，未运行重建脚本；使用 `/auth/login` 获得真实本地 JWT，并在 `AGENT_ROLLOUT_SAMPLE_RATE=1` 的一次性本地进程中验证：

| Query 类型 | HTTP | 实际所有者 | 任务候选 | 墙钟时间 |
|---|---:|---|---:|---:|
| `1+2等于几` | 200 | `controlled_rollout` | 0 | 1282 ms |
| `我是谁？` | 200 | `controlled_rollout` | 0 | 2453 ms |
| 明确明早浇水提醒 | 200 | legacy | 0（未选择植宠） | 3483 ms |

验证后本地 HTTP 服务和本轮临时启动的 MySQL 均已关闭。该证据证明路由、真实 provider、数据库会话保存和 legacy 回退可以在完整 HTTP 链路协同工作；它不是腾讯云 SCF P95 或体验版证据。

## 6. 重大功能变更披露

- **保留**：Chat/Vision、图片/文档、多会话、编辑/撤回、legacy 记忆、published-only RAG、当前植宠事实和确认式任务链路不变；MySQL 与业务 API 仍是事实和正式写入源。
- **删除或改为非默认**：没有删除产品能力。Phase 3 总开关默认关闭；打开后，抽中的普通低风险文本不再由 legacy 回答正则决定能否回答。Shadow 仍可独立关闭，且选中受控灰度时不会重复运行 Shadow。
- **新增**：稳定会话抽样、能力所有权门禁、结果完整性门禁、一次性交换保存、token 记账、脱敏灰度日志、42 场景真实 provider 探针和答案级语义断言。
- **重组**：`chatHandler` 的顺序变为“受控灰度尝试 -> 未接管则 legacy”；用户没有新入口或 UI 变化。
- **未实现**：未迁移任务 proposal、长期记忆、附件、当前植宠/设备事实、高风险处置；未引入官方 PI Core、Runtime Harness、多 Agent、后台自治、checkpoint、硬件写工具或新业务权限。

## 7. 后续闸门

Phase 3 的本地代码和验证可以作为“可部署候选”验收，但不能据此声称体验版已经灰度。若要实际打开目标环境流量，至少还需：

1. 在目标环境配置独立 cohort key，并从 10% 或更低稳定会话比例开始；
2. 验证腾讯云 SCF 冷启动、P50/P95、模型错误率、回落率、token 和知识命中率；
3. 先演练 `AGENT_ROLLOUT_ENABLED=false` 的单开关回滚；
4. 对真实灰度回复做人工质量抽检，日志继续禁止保存原始对话；
5. Phase 4 记忆/会话与 Phase 5 任务候选仍需分别设计和授权，不能从 Phase 3 自动开始。
