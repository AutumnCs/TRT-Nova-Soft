# UI 品味与原型迭代

更新：2026-09-10。当前仅记录后续 UI 优化约定，不启动界面重构。

## 已确认的流程

1. 先理解用户、场景、核心任务和本轮要解决的问题，回顾会议反馈与用户提供的参考。
2. 使用 design-taste-frontend（taste skill）将需求整理成成熟、统一的视觉与交互方向，明确层级、配色、字体、组件尺度和动效用途。
3. 先制作独立 HTML 交互原型，进行测试、体验、反馈和修改，反复迭代直到用户满意。
4. 用户明确同意后，才将确认的方案应用到微信小程序。
5. 在小程序和手机上继续测试、体验、反馈与修正。HTML 认可不等于小程序验收通过。

普通功能 bug 按其行为边界修复，不借机改造整页 UI。参考附件和旧会议中的方案不是立即改动导航、品牌、权限或业务流程的授权。

## 会议反馈中的设计要求

- **小而美**：围绕已有植物养护闭环，不用装饰、庞大按钮和大片空白撑页面。
- **清晰的视觉重点**：首页与花园保持连贯，以正在养的植物及当下养护行动为主角；天气等辅助模块不抢占首屏。
- **紧凑但易操作**：减少松散布局和繁琐步骤，控制按钮视觉体积，同时保留足够的触控区域与可读字号。
- **统一风格**：先确定整体方向，再协调品牌组件、色彩、字重、圆角与间距，避免各模块各用一套配色。
- **有反馈的交互**：切换、按下、弹层和任务状态变化应有适度反馈；动效不能阻塞操作、移动正在阅读的数据或拖慢首次进入。
- **有质量的素材**：避免大量 emoji、默认占位符和未经打磨的图形；选择适合产品气质的素材，并验证小程序上的加载与渲染表现。

## 当前参考方向

用户提供的 garden-refined 原型和“花园手记”截图作为后续讨论的起点：柔和、低饱和的绿色，自然植物插画，清晰文字层级，植物主卡配轻量养护任务。

设计解读：面向日常养植物用户的轻量陪伴型小程序，偏自然、平静、精致；重点是植物归属感与养护行动，不是营销落地页的视觉表演。

参考中的 Tab 名称、布局和每个细节不自动覆盖当前小程序。未来以用户确认过的 HTML 原型为实施依据。本轮没有运行或修改该原型，也没有重新验证其 README 中的性能和无障碍结论。

taste skill 主要面向网页。本项目采用其需求分析、统一性、层级和反馈原则来指导 HTML；落地微信时使用合适的原生组件与资源策略，不照搬 React、Tailwind 或网页滚动动效栈。
