## 我们本来要做什么

不是再做一个植物问答框。学长要的是：**建一盆植物 → 看图问问题 → 确认养护任务 → 打卡 → 记成长 → 下次接着聊。** AI 要记得上下文、说话自然，也不能擅自安排事情。

后来你补充了图片和文档草稿、多会话、长按重新编辑、称呼记忆、无限 Chat/Vision，以及参考 PI 重做 Agent。我们保留原来的四个页面和业务功能，没有把硬件、社区、多 Agent 一起塞进参赛版。

## 你的要求，现在对应到什么

| 你要的 | 现在有的 | 还要注意的 |
|---|---|---|
| 一盆植物能完整养起来 | 建档、封面、任务、周/月日历、打卡、图文日记 | 最后要由你亲自走通；天气失败应提示，不能编数据 |

| 选图后补文字，离开再回来不丢 | 图片与文档草稿、真实分析和重开恢复已复测，包括没有植宠时 | 电脑中注入文件选择结果，不冒充真机文件选择；云端存储仍未验 |
| 消息操作不占地方 | 长按本人消息后出现复制、重新编辑、撤回 | 撤回限最后一轮；助手消息的操作菜单还没做 |

| 页面切换快，交付能看懂 | 已加缓存、保留旧内容、去掉固定等待；这份简版是统一入口 | 首次进入仍慢，不能说已彻底修好 |

Chat/Vision 已取消账户次数上限。拍照仍保留；知识库目前是你批准临时使用的 17 种植物、10 篇文章，不是覆盖所有植物的百科。

## 回头看，之前哪里做得不够好

- **报告写成了开发记录。** 一堆阶段名和测试数，没有先回答你能用什么。现在把入口收成这一份，旧报告只在需要时查。
- **“代码有了”说得太像“体验做好了”。** 记忆功能存在，不代表每段话都记得对；自动测试通过，也不等于你用着顺。下面直接用你以前遇到的例子验。
- **上下文做错了重点。** 之前主要做偏好确认，却没保证“刚说完名字，下一句就能记得”，还会自动清理旧原话。本轮已取消这个清理策略，接通统一上下文；旧策略已经删掉的记录无法倒推恢复。
- **入口文档过时。** 有的还写“Phase 4/5 没开始”，后续接手很容易被带偏；本轮同步修正。
- **测试本身也有疏漏。** 两个测试启动器不认识日常启动器的 Windows 路径，页面测试还会清缓存却不恢复。现在已修正路径，增加测试前保留、测试后恢复缓存，并补了回归测试。
- **云初版的叫法太容易误会。** 它目前是能打包的起步代码，不是拿来就能运行的完整云产品。图片存储、密钥读取和云上验证还需要做。

## 你照着这样验，不用先看技术文档

只操作新建的测试植株、测试消息和无隐私附件，别拿重要数据练删除。每项实际试过再打勾；卡住时记下“在哪一步、问了什么、截图”。

先启动本地服务，然后在微信开发者工具打开同一个项目并编译：

```powershell
cd 'D:\植宠项目\TRT-Nova-Soft\.worktrees\wechat-prd-v0.1\TRT_Nova_MVP_miniprogram_LastScf'
npm run manual-acceptance:start
npm run manual-acceptance:status
```

看到数据库和后端都显示 `READY` 才往下走。重启电脑后要重新启动；别用 `npm run local-db`，那不是普通启动命令。

- [ ] **1. 从首页开始。** 新建一盆“验收月季”，选封面，再退出重进。植物、名字和图片都还在；首页、日历、我的都能打开。首次和第二次切换分开观察。
- [ ] **2. 试普通聊天。** 依次问“你好？”“月季是什么？”“1+2 是多少朵玫瑰？”不能因为问号或植物词就套一段生硬拒绝，也不能给当前植物凭空建任务。
- [ ] **3. 连续对话与自动记忆。** 先不开记忆开关，说“以后叫我 dola 吧”，立刻问“你怎么称呼我”“刚才聊了什么”，应该接得上，不能叫成“dola吧”。点右上“记忆”，开启一次自动摘要，回聊天再说一次称呼，随后新建会话追问，应叫对名字，不弹逐条确认卡。去记忆页修正为“豆包”，新会话应改称豆包；清除后再新建会话，不应恢复旧称呼。关闭时，本会话仍连续，但新会话不读取跨会话摘要。
- [ ] **4. 试图片和文档。** **先不建植宠试一次，有植宠再试一次。** 选一张月季图，确认它只进输入框，补“这是什么，只介绍，不安排任务”再发送。切页面再回来，图片和回答都在，没有多弹一次确认。文档也这样试一次。取消选择不应清掉已有草稿。
- [ ] **5. 试重新编辑。** 平时没有常驻操作按钮；长按自己发过的文字或图片消息，点重新编辑，文字/附件回到输入框。改完发出后继续追问，应沿新分支回答，原对话还在。再试撤回最后一轮。
- [ ] **6. 试任务。** 先说“不要给我创建任务”，应没有候选；再说“明天上午九点提醒我观察这盆月季”。先取消一次，日历不应有任务；重新提出并确认，只出现一条、归属正确。再去日历延期、编辑、完成，首页状态同步。
- [ ] **7. 试养护记录。** 给这盆植物写一条带图日记，重开检查，再编辑它。回 AI 问这盆植物的养护记录，应依据实际记录回答，不编造做过的事。知识问题的来源也点开核对。
- [ ] **8. 收尾检查。** 个人资料头像和对齐、知识库返回与上滑、关于页面返回、城市天气、缓存清理、退出登录。清缓存不能把服务器上的照片删掉。另建一盆测试植物，检查两盆的聊天、任务、日记不会串。

输入框先复测这几下：重新编译后，先写“前”，从“＋ → 选择功能”选“判断是否浇水”。在功能右侧连续输入 `123456111111`，字符应按顺序留在右侧。连续退格几次，应只删除左边的字符，光标不跳到开头。再把光标放到功能紧挨着的右边，按一次 Backspace：只删除整枚功能，“前”和右边剩下的文字都保留；继续输入“中”，应插在原位置。最后试 Enter 换行和箭头发送。没有叉号或自动插入的提示词，创建任务、管理记忆仍走原有表单。

摘要也单独试一下：进入“记忆 → 编辑摘要”，整段改成“你希望我称呼你为豆包。你喜欢月季，偏好简短回答。”，保存后重进，应保持这段原文。再新建会话问称呼。如果保存失败，草稿应还在；聊天期间摘要更新了，会先要求你对照新版，不直接覆盖。

这八步是主线，不代表所有异常都测完。要做最终全功能签字，再按[详细验收底稿](../.././m7-final-human-acceptance-guide.md)检查坏图、断网、重复点击、归档/永久删除、周期任务、账号隔离和过期数据。真机拍照授权、物理震动、手机冷启动留在 M8，不用电脑测试冒充。

## 现在的记忆怎么工作

分清三样东西就够了：

| 层次 | 现在怎么做 |
|---|---|
| 这段对话的原始记录 | 按账号、会话保存完整有效历史，重新编辑保留分支。取消自动丢弃旧轮次；原文保留到用户删除。已被旧策略清理的原文不能凭空恢复。 |
| 这一轮给模型的上下文 | 短对话带原文；长对话带最近原文和自动整理的前文摘要，必要时查回原话。当前对话里的称呼优先于账号昵称，所有聊天路径都要用同一套上下文。 |
| 跨会话摘要 | 用户开启一次后，AI 在每个完成的轮次后增量判断是否更新称呼、习惯和稳定偏好，不再逐条要求确认。用户可以看、纠正、关闭或遗忘；不用手工维护才能生效。 |

PI 源码确实区分完整会话记录和本轮模型上下文，使用 JSONL 会话树、摘要和保留的最近消息，而不是只挂一个偏好列表。[PI 会话源码](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/session-manager.ts)。我们的后端是 SCF/MySQL，建议沿用数据库保存会话，不把云函数临时文件变成第二套数据源。**保存原文不等于每轮无限塞给模型，也不保证模型逐字记住。** [OpenAI 的上下文说明](https://developers.openai.com/api/docs/guides/conversation-state)同样明确上下文窗口有限。

你给的 ChatGPT 截图体现了自动摘要和用户管理，但公开资料不足以证明其内部每轮都会全量重写。本版做的是增量整理：先保存回复，再用一次短模型请求提取有原话来源的昵称、交流/养护偏好和园艺兴趣，同时生成一段可读摘要。没有新信息就不更新。后台仍保留最多30项语义事实，用于去重、来源清理和隔离；你看到、编辑的是整段文字，最多4000字，不需要逐项维护。整体编辑保存最多等待15秒整理，失败保留原摘要和草稿。

这次没有把回复与摘要硬塞进同一个输出：文字、图片和文档的返回格式不同，先用共用的轮后整理器接齐，方便检验和维护。代价是开启自动摘要后多一次短请求；每次摘要请求最多等6秒，失败时保留原对话并提示“跨会话摘要暂未更新”，不会承诺已经保存，也没有云函数返回后的后台计时器。暂不自动补提取失败轮次，可再次告诉它。以后可以在保持接口和测试不变的前提下合并推理，减少等待。

长会话不是无限塞给模型：近期最多8轮完整原话、约2万字符，较早内容用最多3000字摘要；本轮最多补做3批，没整理完会提示，原话仍可查。页面每次加载20轮，点“查看更早的对话”继续看。模型还有只读的本会话原话检索工具，不能指定别人的账号或任意会话。

关闭摘要不删除原会话；清除摘要也不等于删掉当前会话里的原话。重新编辑只沿新分支走，不把原分支后半段带进来；撤回会让会话摘要失效，并移除来源于该轮的自动摘要。正式任务和档案仍须确认。旧版偏好记录保留在记忆页折叠区，正常对话不再拿它冒充新摘要。

现有 Agent 仍是借鉴 PI 分工的内部 `PlantPetRuntime`，没有直接搬入完整 PI 编程助手；图片/文档还是专用处理链。当前也没有逐字流式输出、知识图谱或完整关系系统。

本轮看实际截图还发现了小毛病：部分来源日期显示成很长的英文，回复中的 Markdown 标记有时直接露出来。这些显示细节尚未修，不算已经打磨好了。

以后维护：新增植物知识走审核发布；换模型改模型适配层；加功能先做受控业务接口，再接工具和确认页面。别让模型直接拿数据库或设备控制权限。代码位置与维护说明放在[开发者架构入口](../.././current-architecture.md)，不用现在逐个读。
