## 3. 不应在云迁移时“恢复掉”的长期正确设计

以下能力虽然服务于本地验收，但不是应删除的妥协：

1. **运行环境门禁**：trial/release 拒绝 localhost，应长期保留。
2. **JWT fail-closed 与 owner 隔离**：正式云端仍必须保留，不能恢复旧 openid 回退。
3. **永久 fileID 与展示 URL/缓存路径分离**：云存储同样需要；`wx.env.USER_DATA_PATH` 只作可清理显示缓存，不是业务真相。
4. **本地 smoke/E2E 和测试数据库脚本**：可长期留在仓库作为回归工具，只需确保不进入云部署包、不作为正式登录或正式数据来源。
5. **PlantPet、CareTask、成长日记及媒体引用字段**：属于正式业务模型，云迁移时要迁移和验证，而不是回退到旧设备/临时路径模型。
6. **天气隐私与事实边界**：长期只保存 LocationID、城市、行政区和选择来源，不保存精确经纬度；客户端不持有天气私钥；无真实数据时不展示示例数值。这些是正式设计，不是本地妥协。
7. **AI 写入确认与证据边界**：Agent 只生成候选，任务和诊断必须由用户确认后经业务 API 写入；RAG 只消费已发布内容，无来源时明确未知；跨会话摘要由用户一次开启后自动维护，保留来源、时间、版本和关闭/遗忘控制。旧显式偏好保留兼容，不能误写成每轮摘要都需要确认。这些是长期正确设计，不应在云迁移时删除。
8. **事件支持的会话投影与幂等 tombstone**：`ai_messages` 可读账本、`ai_conversation_events` 审计、有效分支投影、`clientTurnKey`、撤回/裁剪后不可重放都属于跨环境一致性约束。云迁移不能把它们简化成无分支的聊天数组，也不能为了删内容而释放旧幂等 key。
9. **proposal 与正式业务对象分权**：`ai_action_proposals` 可以由 Agent 生成，但 `ai_memories`/`todos` 只有用户确认后由 `api-scf` 写入；owner、状态、过期、PlantPet 与幂等必须在 API 侧复验。这是正式权限模型，不是本地绕行。
10. **前端异步 scope 隔离**：PlantPet、会话和 epoch 三元 scope 防止旧请求覆盖新画面。云端网络更慢、重试更多，这项保护更应保留，不能在迁移时移除。
11. **Runtime 替换 seam**：标准 Node 20 的 `PlantPetRuntime` 只是 PI 语义兼容的最小内部实现，不是官方 PI Core。本地到云端迁移不要求改用官方包；若未来切换 Node 22 Custom Runtime/镜像或官方 Core，必须另做依赖、打包、冷启动、工具协议和回滚评审。

本机演练采用真实独立 MySQL 和打包业务代码；微信、模型、COS、SSM 的外部服务是受控替身。另有实际 SDK 对本机 HTTP 服务的签名/令牌/字节传输测试。它们不等于真实云权限、服务质量或实体手机通过。

新增的候选环境取舍也需披露：

- 采用认证后的 API 字节代理读写小附件，不依赖过期 CloudBase；仍受现有 2 MiB 附件限制，解析逐个请求以控制响应大小。
- GC 每次最多处理 2 个对象；上传结果不明确时等待一天再清理，失败指数退避。先保证不误删，真实部署后需监测积压，不承诺即时物理删除。
- SSM 在冷启动读取，同温实例缓存；密钥轮换需更新函数版本/实例。不能把配置引用当成已经读取过真实秘密。
- 服务器 Agent 预算 90 秒、客户端 60 秒；慢模型仍可能超时。保留原重试幂等机制，本轮没有加后台自治或重写 Agent。
- 旧 IoT/设备写入继续受控关闭；当前候选不包含管理后台。它们不是本轮小程序云适配通过的附带结论。
- 正常会话不采用旧版 20 轮/30 天删除策略。本文第 4 节历史记录中的旧策略仅描述当时实现，已被后续上下文需求覆盖。

未实施本地用户数据搬迁：本地开发 openid 与真实账号的映射、local:// BLOB 到 COS 的转存/校验/引用替换仍需另行批准。不把假身份和验收样本直接装入云库。
