- **新增确认式长期记忆**：受控 Runtime 登记 `recall_relevant_memories` 和 `propose_memory_candidate`；只召回与当前 Query 相关且用户已确认的 `user_preference`。明确称呼偏好先成为 24 小时 `pending` memory proposal，用户在消息卡确认后才由 `/ai/memory-proposal-confirm` 写 `ai_memories.user_confirmed=1`；可取消，重复确认幂等，敏感信息在工具和 API 双层拒绝。账号资料、植宠档案、任务、日记和诊断不会被复制成模型自由文本长期记忆。
- **新增任务 proposal 闭环**：受控 Runtime 只有在严格 `request` 任务意图时开放 `get_selected_plant + propose_care_task`；普通建议、模糊任务词和明确否定为零候选。候选原子保存为 `pending`，前端从后端重新读取并进入“预览并编辑”，锁定 PlantPet 归属但允许修改字段；`api-scf` 在确认时重新验证 owner、类型/状态/过期、PlantPet 和字段，并用 `(openid, proposal_key)` 幂等写正式任务。普通 `/care/task-create` 拒绝伪装 AI 来源的绕过调用。
- **Vision 边界**：Vision 普通建议不产生任务。只有用户明确请求任务、当前 PlantPet 存在、分析确定为植物、置信度至少 0.7 的候选名称与当前 PlantPet 昵称/品种匹配且存在建议动作时，图片轮次才会保存 `pending` task proposal；模型 `advice` 本身没有副作用权限。
- **前端异步隔离**：助手会话加载、文本、图片和文档发送增加 `PlantPet + session + epoch` scope guard。切换 PlantPet、切换会话或页面卸载会使旧 scope 失效；旧请求可以在服务端完成，但不得覆盖新页面状态，未认领的过期图片媒体会尝试清理。
- **重组**：`chatHandler` 现在是“默认关闭的受控 Runtime 尝试 -> 结果门禁 -> 原子 exchange/proposal 保存；未选择或未通过则 legacy 回落”。模型只拿到本轮 allowlist；proposal 生成与正式业务写入被拆成 Agent 和 `api-scf` 两个权限边界。当前仍保留较重的 legacy controller，尚未完成纯应用控制器化。
- **框架说明**：生产源码是标准 Node 20 可运行、PI 语义兼容的最小内部 `PlantPetRuntime`，不是官方 `pi-agent-core`、PI `AgentHarness` 或 coding agent。PI Core 仅在隔离 Spike 中验证过；没有把其 Node 22.19 支持线或本地兼容样本冒充生产接入。
